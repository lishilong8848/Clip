# 旅游规划技能

## 为什么这个技能必须先搜索再规划

旅游信息的时效性极强：门票价格、开放时间、预约政策、交通班次、景区限流规则在节假日前后经常变动，模型内部知识必然过时。**任何行程决策必须建立在实时搜索结果之上**，而不是模型记忆。规划过程中的每个关键事实（价格、时间、政策）都要标注信息日期与来源，方便用户核验。

## 整体流程

1. 需求澄清（目的地、时间、同行人、预算、偏好）
2. 全网公开搜索调研（并行搜索 + 关键信息核验）
3. 天气查询（规划期气候研判 + 出发前实时复核）
4. 行程编排（逐日方案 + 备选）
5. 路线图（整体动线 + 每日节点连线图）
6. 预算测算（分项明细，可出 Excel）
7. 实用清单（预约、证件、天气、避坑）
8. 交付（结构化文档 + 成果入库）

## 第一步：需求澄清

用最少的问题收集齐以下信息（缺项用合理默认值补足，不要逐条盘问）：

| 信息 | 说明 | 缺省默认 |
|---|---|---|
| 目的地 | 具体城市/景区，或只说类型（海边/山里/古城） | 需要用户给出 |
| 时间与天数 | 出发/返回日期，或"X天" | 需要用户给出 |
| 同行人结构 | 是否带娃（年龄）、带老人、纯成人 | **决定行程节奏的核心变量** |
| 预算 | 总预算或人均预算 | 按目的地常规水平估算并标注 |
| 交通偏好 | 自驾/高铁/飞机 | 按目的地推断 |
| 节奏偏好 | 紧凑打卡 or 休闲躺平 | 带娃/带老人默认休闲 |

**同行人结构决定节奏**（这是行程编排的核心原则）：
- 带低龄儿童（如小学生）：半天一个主景点 + 午休时间 + 亲子设施优先，单日移动距离要小
- 带老人：少爬坡、少暴走、安排休息点，医疗便利性要考虑；长途车程安排两人轮换驾驶
- 纯成人：可以紧凑，但仍保留弹性

**门票优惠预判**（预算时用）：儿童一般按身高免票（如 1.2m 以下）或学生半价；老人常见 60—64 岁半价、65 岁以上免票（各地不同，预算按优惠价计并在备注标注"以现场核验为准"）。同行人构成确认时若用户没给年龄/身高，预算里按优惠价计并写明假设，交付时提示现场核验。

## 第二步：全网公开搜索调研

这是技能的核心动作。**禁止直接凭模型知识写景点和价格**。

### 2.1 并行发起搜索

围绕以下维度同时搜索（一次发起多个独立搜索，互不依赖）：

1. **目的地整体攻略**：「目的地 + 旅游攻略 + 最新」——了解主流玩法、必去清单、最新变化
2. **门票与预约**：「景点名 + 门票价格 + 预约」——重点查是否需要提前预约/限流（热门景点节假日必查）
3. **交通**：「目的地 + 交通攻略」——到达交通、市内交通、自驾停车/限行政策
4. **住宿**：「目的地 + 住宿推荐 + 区域」——哪个区域住最方便，结合行程动线选住宿区
5. **气候背景**：「目的地 + 月份 + 气候/天气特点」——该季节的常规天气、雨季/雪季、防晒防暑需要（与专节实时查询互补）
6. **政策与避坑**：「目的地 + 最新政策/避坑/注意事项」——如景区调整、管制、消费陷阱

搜索问题库见 `references/search-question-library.md`，按出行场景选用。

### 2.2 天气查询（两个时点，缺一不可）

天气影响行程的程度超过预期：雨天山上封路、暑期户外暴晒、冬天缆车停运。查询分两个时点：

**时点一：规划期气候研判**（编排行程时）
- 查目的地该季节的气候特征（气温区间、降水概率、是否台风/暴雨季），决定室内外景点配比和穿衣建议
- 来源：权威天气源的历史气候数据或「目的地 + 月份 + 天气」搜索结果

**时点二：出发前实时复核**（交付方案时执行，或提醒用户执行）
- 用天气查询工具查出行日期逐日天气预报（优先调用腾讯新闻 CLI 的 `weather` 命令，或权威天气网站）
- **降级方案**：天气工具不可用（如未配置 API key）时，用 web 搜索「目的地 + 日期 + 天气预报」，优先天气网/中国天气网等权威源的 15 天预报页，标注信息日期
- **逐日 emoji 展示**：天气用图标直观呈现——☀️晴 ☁️阴 ⛅多云 🌧️雨 ⛈️雷阵雨，转换天气用箭头（如"⛅→☀️"），每天一行：`8/18 ☀️ 20-31℃`；同一行程涉及多地时按天分列（D1 关山、D3 宕昌、D5 武都…）
- 逐日输出：日期 / 天气 emoji / 温度区间 / 穿衣建议 / **对当日行程的影响**（如"第2天有雨→上午改室内备选"）
- 实时天气与规划期气候冲突时，以实时为准，并主动调整行程编排

### 2.3 关键信息核验与标注

- **价格、开放时间、预约要求**这类一旦出错影响很大的信息，用 fetch 打开原始来源（景区官网、官方公众号、权威新闻）确认，不要只信二手攻略
- 每条关键信息标注：**信息来源 + 信息日期**，格式如 `（据景区官网 2026-08 信息）`
- 同一信息多个来源冲突时，取官方来源，并在交付时提示用户出发前再确认

### 2.4 搜索纪律

- 用户没指定目的地时，先搜「最佳旅行目的地 + 月份/季节 + 同行人类型」做推荐，给出 2-3 个候选让用户选
- 注意当前日期与节假日（如暑期、国庆），搜索时带上月份，避免搜到过期攻略

## 第三步：行程编排

1. **定动线**：按住宿区域为中心，把景点按地理相邻度分组，避免来回折返
2. **逐日排程**：每天安排 2-3 个主要节点（亲子游 1-2 个），标注上午/下午/晚间，留出弹性时间
3. **备选方案**：每个主要景点给 1 个备选（天气不佳/预约满/临时关闭时的替代），雨天备选尤其重要
4. **节奏校验**：对照同行人结构检查——孩子是否有午休、老人是否爬坡太多、吃饭是否有着落（景区内 vs 周边商圈）

## 第四步：路线图

路线图让用户对"怎么走"一目了然，是方案里最能直观体现专业度的部分，分三个层次：

1. **整体到达路线**：出发地 → 目的地的交通方案（高铁/飞机/自驾），标注车次/航班类型、时长、换乘点、费用区间；自驾注明主要高速与里程
2. **每日动线**：以住宿地为中心，把当天各节点串成一条不折返的动线——每个节点间标注**交通方式 + 大致耗时**（如"熊猫基地 →（地铁3号线，40分钟）→ 宽窄巷子"）
3. **路线示意图**（用户需要时生成）：
   - **真实地图模式（推荐，跨城自驾必用）**：用 `scripts/map_overlay.py`——以**高德/腾讯公开地图瓦片为真实底图**（标准街道图，含中文地名），节点按实际经纬度定位，逐日分色连线标注交通信息，生成"网上真实地图"风格的路线图；瓦片双源下载（高德优先、腾讯兜底），自动缓存
   - **地图定位模式（无网络时）**：`scripts/route_map.py` 的 **geo 模式**——按真实经纬度绘制地图风格路线图（经纬度网格底图），不依赖外部地图服务
   - 节点模式（不涉及地理跨度时）：每天一个色块/一条线，标注节点、交通方式与耗时
   - 均支持无绘图环境时降级文本路线图

动线规划要点：同一天内景点按地理相邻度排序，避免东西往返；亲子/老人行程单日换乘不超过 2-3 次；晚间回住宿地的路线要预留末班车/打车时间。

## 第五步：预算测算

按以下分项生成明细（金额用人民币，单位标注清楚）：

| 分项 | 内容 | 备注 |
|---|---|---|
| 大交通 | 往返机票/高铁/油费过路费 | 自驾记得算油费+过路费+停车 |
| 住宿 | 每晚房费 × 晚数 | 标注酒店区域与房型 |
| 门票 | 逐景点列单价 × 人数 | 儿童/老人优惠票单独算 |
| 市内交通 | 打车/地铁/租车 | |
| 餐饮 | 每日预算 × 天数 | |
| 其他 | 购物、保险、应急 | 建议预留 10% 弹性 |

用户有 Excel 偏好时输出预算表文件（`budget.xlsx`，含分项明细与合计），可复用 `scripts/budget_table.py`（接受预算 JSON 自动生成 xlsx），否则在文档内用表格呈现。金额口径与用户确认（总预算 vs 人均）。

**多来源价格冲突处理**：同一景点不同平台价格差异较大时（如某景区门票 80—149 元），预算按主流/官方价计入，文档中注明区间与"以官方当日为准"，并说明若按高价计的上浮空间。

## 第六步：实用清单

交付物附三张清单：
1. **预约提醒**：哪些景点/票需提前几天预约、几点放票、要带什么证件
2. **行前准备**：证件、衣物（按天气）、药品（晕车/肠胃/过敏）、充电设备、孩子用品
3. **避坑提示**：搜索中发现的消费陷阱、管制信息、高峰期时段、停车/排队建议

## 第七步：交付

标准输出结构（见 `references/output-structure.md`）：
- 方案摘要（目的地、时间、同行人、预算、总览一句话）
- 目的地调研（含信息来源与日期标注）
- 天气研判（规划期气候 + 逐日实时预报，含对行程的影响）
- 逐日行程（含备选方案）
- 路线图（整体到达路线 + 每日动线，可附路线示意图）
- 预算明细
- 实用清单

**交付前确认门**：方案框架（目的地/天数/预算档位/节奏）应先给用户确认，确认后再细化到逐日行程与预算。用户赶时间或已明确要全量方案时，可一次交付并注明可调整点。

**Word 交付格式**：用户要求 Word 文件时，默认按 GB/T 9704-2012 公文格式排版（大标题小标宋二号居中、一级标题黑体三号、二级标题楷体三号加粗、正文仿宋三号行距固定28磅首行缩进2字符、表格黑色0.5磅单线全边框表头浅灰底纹、页脚"— 页码 —"居中），除非用户明确要求非公文格式；路线图 PNG 嵌入对应章节，预算用表格呈现。

**成果入库**：生成的文件（Word/Excel/图片）按平台成果入库规范归档，交付时给出可点击查阅入口。

## 工作流示例

### 示例 1：暑期亲子游（带 7 岁儿童，4 天 3 晚）
1. 澄清：目的地成都，暑期，两大一小，预算 8000，高铁
2. 搜索：成都亲子游攻略、熊猫基地门票预约、都江堰预约政策、成都暑期气候、住宿区域推荐（并行 5 路）
3. 天气：规划期查暑期气候（湿热、多午后雷阵雨）→ 出发前查逐日预报，安排雨天备选
4. 编排：每天 1 个主景点（熊猫基地上午+午休+宽窄巷子傍晚），备选室内科技馆（防暑雨）
5. 路线图：高铁到达 → 每日动线（熊猫基地→地铁→宽窄巷子），路线示意图（PNG）
6. 预算：高铁往返 1400 + 住宿 3 晚 1500 + 门票 800 + 市内交通 500 + 餐饮 1800 + 其他 500 ≈ 6500，留 1500 弹性
7. 清单：熊猫基地需提前预约、暑期防晒防暑、儿童证件提醒

### 示例 2：带老人自驾山水游（3 天 2 晚）
1. 澄清：目的地某山水景区，自驾，带 65 岁老人，休闲为主
2. 搜索：景区开放时间与索道信息、自驾停车与限行、周边住宿（离景区近、有电梯）、该季节气候
3. 天气：规划期查雨季分布 → 出发前逐日预报，雨天改室内/取消爬山
4. 编排：每天上午 1 个景点 + 中午回酒店休息 + 下午轻量活动，少爬坡（索道优先）
5. 路线图：自驾高速动线（标注服务区停靠点）+ 每日景区内动线，索道上下山标注
6. 预算：油费过路费 + 住宿 2 晚 + 门票（老人半价）+ 餐饮，逐项列明
7. 清单：索道票价与排队时间、老人常备药、停车攻略

## 边界

- 不做实际预订（机票/酒店/门票下单），只做规划与信息整理
- 不办签证、不买保险
- 信息以搜索结果的官方来源为准，标注日期，提醒用户出发前复核
