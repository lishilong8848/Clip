# 体育赛程查询能力

使用 `tencent-news-cli` 查询腾讯新闻已接入的体育赛事列表，以及赛事下的比赛日程、对阵、比分和直播链接。

## 执行流程

1. 始终先执行 `sh scripts/run-cli.sh sport --help`；Windows 使用 `powershell scripts/run-cli.ps1 sport --help`。子命令、参数名和默认值以当前帮助为准。
2. 识别请求类型：
   - **赛事查询**（"西甲比赛有什么"、"中超这周有哪些比赛"）：用户指明了赛事。
   - **球队查询**（"国安最近有哪些比赛"、"皇马下场踢谁"）：用户指明了球队，没有指明赛事。
   - **赛事列表**（"支持哪些赛事"、"能查什么比赛"）：直接展示赛事列表。
3. 执行 `sh scripts/run-cli.sh sport tab-list` 获取当前支持的赛事名称和赛事 ID。每次会话至少执行一次，不要硬编码赛事 ID；赛事列表会变化。
4. 确定要查询的赛事 ID：
   - 赛事查询：把用户说的赛事名称匹配到 tab-list 中的条目，接受常见别名（"英超" 与 "英格兰超级联赛"，"欧冠" 与 "欧洲冠军联赛"）。
   - 球队查询：先判断该球队参加哪些赛事，再在 tab-list 中找到对应赛事 ID。CLI 只有按赛事全量拉取的接口，没有按球队名查询的能力，判断顺序如下，比赛数据本身仍然只能来自 CLI：
     1. 先查本文「球队与赛事对应表」。国内赛事的球队名单来自 CLI 实际返回，命中即用。
     2. 表中没有的，用模型自身的常识判断，主要是欧洲五大联赛、欧冠欧联、NBA 等国际赛事的球队。
     3. 仍不确定时，按「未知球队兜底流程」处理。
     - 一支球队可能同时参加多项赛事，例如皇马参加西甲和欧冠、国安参加中超和亚冠精英联赛。tab-list 中出现的相关赛事都要查询，结果合并后按时间排序。
     - 球队名称在多项赛事中重复时（"河南队" 是中超河南队，"常州队" 是苏超常州队，"西班牙人" 是西甲球队而非西班牙国家队），优先按对应表和 tab-list 中存在的赛事解释；仍有歧义时向用户说明按哪种理解查询，或一次查询多项赛事分别展示。
     - 无法判断球队所属赛事，或该赛事不在 tab-list 中时，如实说明当前 CLI 不覆盖该赛事，不用其他数据源补做。
   - tab-list 中名为 "热门" 的条目 `competition_id` 为空，不能用于 match-list。
5. 确定时间范围：
   - 用户给出明确日期或区间时按用户给的。
   - "最近"、"近期"、未指定时间：默认从今天往前 3 天的 00:00:00 到往后 5 天的 00:00:00。
   - "今天"、"明天"、"这周末"：换算成对应日期的整天区间。
   - "下一场"、"下场比赛"：从当前时间开始查未来 14 天，只展示时间最早的一场。
   - 时间参数格式固定为 `"2006-01-02 15:04:05"`，按北京时间填写。
6. 对每个赛事 ID 执行 `sh scripts/run-cli.sh sport match-list --competition-id <ID> --start-time "<开始>" --end-time "<结束>"`。
   - 球队查询在返回结果中按球队名称过滤，匹配 `title`、`left_team_name` 或 `player[].name`；`player` 可能为空（非对阵类项目或部分赛事），此时只按 `title` 匹配。球队名称做宽松匹配，按核心词而不是全名："国安" 匹配 "北京国安"，"河南" 匹配 "河南队" 和 "河南俱乐部彩陶坊"，"徐州" 匹配 "徐州队"。赞助商冠名会随赛季变化，不要因为全名不同而漏掉。
   - 结果按开始时间升序，每页固定 15 条，没有条数参数。`has_more` 为 `true` 时把 `asc_cursor.cursor_time`（也就是最后一条的 `start_time`）作为 `--cursor-time` 再查一次，返回的是该时间之后的比赛。翻页不超过 3 次。
   - 需要按球队过滤时使用 `--format json`，字段更完整；纯赛事查询可直接使用文本输出。
7. 所有实际调用都走 `run-cli`，不直接执行 `platform.cliPath`。

截至 2026-09-11 核实（CLI v1.0.16，build 2026-09-11），CLI 提供 `sport tab-list` 和 `sport match-list --competition-id --start-time --end-time --cursor-time --format`，match-list 没有按球队过滤的参数，CLI 侧已确认不会提供。此信息仅供理解，版本可能变化，每次仍以实际帮助与返回为准。

## 数据理解

- 时间范围内没有比赛时，JSON 的 `data.data` 为 `[]`（旧版本可能是 `null`），文本输出为 `暂无比赛数据`；都按"无比赛"处理，不是错误，也不要换其他数据源。
- `start_time` 形如 `2026-08-28T19:35:00+08:00`，带北京时间偏移，展示时直接取日期和时分。旧版本输出 `2026-08-28T19:35:00Z`，`Z` 后缀同样表示北京时间，不做时区换算。
- `asc_cursor.cursor_time` 和 `desc_cursor.cursor_time` 仍是 `Z` 后缀，同为北京时间，回传给 `--cursor-time` 时原样使用即可。
- `end_time` 字段不存在、为空、为 `1970-01-01T00:00:00Z` 或文本输出中的 `-` 都表示无结束时间，直接省略。
- `score` 中 `id` 对应 `player[].id`，按 `player` 顺序输出 `左队比分:右队比分`。开始时间晚于当前时间的比赛尚未开始，**不展示比分**，即使返回值为 `0:0`；开始时间早于当前时间的比赛展示比分。
- 部分赛事的条目没有 `player`，只有 `title`，例如排超 B 级、乒乓球单打；乒乓球等个人项目的 `player[].name` 是运动员而不是球队。
- `live_url` 为直播间或比赛页链接，存在时展示为 `[进入直播间>>](URL)`。
- `title` 通常已包含轮次和对阵，例如 `第25轮 大连英博海发 VS 北京国安`，可直接作为比赛名称。

### 未知球队兜底流程

对应表和常识都无法确定球队所属赛事时：

1. 按用户提到的项目（足球 / 篮球 / 排球）或球队名特征（"女足"、"女篮"）缩小到 tab-list 中同一项目的赛事。
2. 用同一时间范围依次查询这些赛事，最多查 4 个，每个赛事最多翻 1 页，在返回中按核心词匹配。
3. 命中即停止；全部未命中时说明"当前支持的赛事中没有找到该球队的比赛"，列出实际查过的赛事，不用其他数据源补做，也不要猜测赛程。

## 输出规则

- 每场比赛一行：`日期 时间 赛事 左队 vs 右队 [比分] [进入直播间>>](URL)`。比分只在比赛已开始后展示。
- 球队查询合并多项赛事时按开始时间升序排列，赛事名写在每行中。
- 赛事查询按开始时间升序，同一天的比赛可按日期分组。
- 时间范围内没有比赛时说明"该时间段内暂无比赛"，并给出实际查询的赛事和时间范围；不要扩大范围到其他数据源，也不要编造赛程。
- 全部内容末尾仅出现一次 `**来源：腾讯新闻**`。
- 只展示 CLI 实际返回的字段；缺失字段省略，不编造。
- 不展示 traceid、请求参数或内部日志。

示例：

```markdown
## 北京国安近期比赛

- 2026-08-28 19:35 中超 大连英博海发 vs 北京国安 1:1 [进入直播间>>](http://view.inews.qq.com/a/RLV2026082214132200)
- 2026-09-03 19:00 中超 北京国安 vs 兰州竞技 [进入直播间>>](http://view.inews.qq.com/a/RLV2026082214132300)

**来源：腾讯新闻**
```

## 边界

- 只支持查询赛程和比赛结果；积分榜、球员数据、赛事新闻、比赛集锦不在本能力范围内，当前帮助没有对应命令时如实说明。
- 不创建订阅、定时任务或比赛提醒，除非用户明确要求且其他能力说明允许。
- 不用模型记忆补充比分、时间或直播链接。允许使用常识的只有"球队属于哪个赛事"这一个判断。

## CLI 失败处理

CLI 非零退出、超时或出现权限/安全错误时立即停止，不重试、不换命令、不使用其他数据源补做。根据错误引导：

- Gatekeeper（`cannot be opened`、`not verified`）：系统设置 → 隐私与安全性 →「仍要打开」；
- 企业安全软件或网络拦截（`connection refused`、防火墙拦截）：在安全提示中选择「信任」或「允许」；
- 权限不足（`permission denied`）：执行 `chmod +x <cliPath>`；
- 提示 `unknown command "sport"` 或帮助中没有 `sport`：当前 CLI 版本过旧，按 SKILL.md「Phase 1」执行更新后重试；
- 其他错误：展示完整错误并请用户处理。

用户确认处理完成后才可重试；持续失败时只说明当前无法查询及原因。
