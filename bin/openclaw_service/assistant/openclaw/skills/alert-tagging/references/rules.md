# 现场告警打标规则（完整参考）

来源：《现场告警打标规则指引》（EA118 机房动环告警，当周夜班值班员每周六夜班核查）。

## 13 类标签总览

| 大类 | 标签 | 概念 |
|---|---|---|
| 预期内（7 类） | 变更 / 维护 / 检修 / 设备轮巡 / 设备调整 / 低负荷 / 上下电 | 提前预知 / 发了通告，告警出现即可打标 |
| 预期外（6 类） | 设备故障 / 人为误操作 / 通讯故障 / 超电 / 环境参数异常 / 未知原因 | 设备 / 人为 / 环境突发，需要查根因 |

## 一、预期内告警（7 类）

### 1.【变更】
- 适用规则：变更窗口期内，由正常变更操作步骤触发的告警
- 不适用：变更范围以外的设备、非预期的误操作引发的告警
- 示例：蓄电池在线核容变更、动环系统双机热备切换变更、HVDC 程序升级变更、柴发空载测试、依米康空调软件更新测试、蓄冷罐控制器更换

### 2.【维护】
- 适用规则：计划性 / 非计划性维护，发了维护通告后产生的告警
- ⚠️ 注意：
  - 阿里的计划性维护通告中**不要描述为非计划性**（措辞有误仍归【维护】，见易错点）
  - 需要提变更的维护：维护通告 + 变更通告**都要发**（多标签场景）
- 示例：定压补水系统月度维护、电池周期性均充、柴油发电机空载测试维护、蓄电池放电测试维护、水质循环、变频器柜端子紧固、内阻刷新

### 3.【检修】
- 适用规则：提前预知的设备检修（不需要提交变更）引发的告警
- 打标要点：
  - 维修未完成时确认打标 → 说明**故障原因 + 当前处理状态**
  - 检修后确认打标 → 说明**是否已完成 + 故障原因 / 修复方式**
- 检修通告三要素：园区机房 + 楼栋、故障设备编号、故障现象或原因（不要写发现方式）+ 风险等级（低/中/高）
- 示例：精密空调检修、蓄电池更换、HVDC 零飘更换直流采样盒、电加热传感器检修、冷冻二次泵检修、蓄冷罐控制器检修、蓄冷罐液位计检修、清洗冷冻二次泵 Y 滤、ATS 通讯故障断电检修

### 4.【设备轮巡】
- 适用规则：提前预知的设备轮巡，发了通告后引发的告警
- 通告三要素：告警范围、会产生告警的设备清单、设备编号
- 示例：制冷单元轮巡、空调轮巡、二次泵轮巡、变频补水机组轮巡、HVDC 模块休眠模式定期轮巡

### 5.【设备调整】
- 适用规则：发了调整通告后，操作调整范围内设备产生的告警
- 通告三要素（与设备轮巡一致）：告警范围、设备清单、设备编号
- 示例：空调运行数量调整、制冷单元运行模式调整、冷塔风扇数量调整、对空调进行开关机

### 6.【低负荷】
- 适用规则：机柜负荷较小、接近于 0
- 示例：机柜负荷小，电流波动

### 7.【上下电】
- 适用规则：提前预知的机柜上下电（不需要提交变更）引发的告警
- 示例：机柜上电、机柜下电

## 二、预期外告警（6 类）

### 8.【设备故障】
- 适用规则：预期外的设备突发故障引发的告警
- 示例：恒湿机排水阀故障、ATS 程序卡死

### 9.【人为误操作】
- 适用规则：人为误触或误操作引发的告警
- 归属说明：变更 / 维护 / 检修期间的预期外人为误操作 → 仍归属【人为误操作】
- 示例：视具体场景填写

### 10.【通讯故障】
- 适用规则：弱电通讯系统（**动环监控设备故障、传输链路中断、点位映射错误**）引发的告警
- 典型场景：通讯线松动晃一下 / 拧一下就恢复 —— **不用检修设备**
- 示例：通讯误告警

### 11.【超电】
- 适用规则：PDU / 机柜 / 列头柜负载率超过限定阈值，由**业务突增**引发的告警
- 怎么判断：未发过业务扩容通告的情况下，负载率突增 → 归【超电】
- 示例：IT 功率波动

### 12.【环境参数异常】
- 适用规则：包间温湿度波动、外市电电压波动、自然环境变化引发的告警
- 示例：机房高湿告警、机房高温告警、IT 服务器上架施工盲板拆除、外市电电压波动、市政水压波动、下雨天漏水导致漏水绳告警

### 13.【未知原因】
- 适用规则：告警出现但无法归到 1-12 类任一项
- 处理：分析根因 + 补打正确标签 + 在周报里反馈新增类别建议（推动规则更新）

## 三、统计周报口径

- 周报统计表按"预期内总数（变更/维护/检修/设备轮巡/设备调整/低负荷/上下电）"与"预期外总数（设备故障/人为误操作/通讯故障/超电/环境参数异常/未知原因）"两类汇总
- 盯两个点：
  - 预期外告警 = 异常波动信号 → 必须分析根因
  - "未知原因"必须清零 → 视为打标遗漏 / 反馈新类别建议

## 四、易错点速查（打标必查）

| 场景 | 应打标为 | 不应打为 | 备注 |
|---|---|---|---|
| 计划性维护，阿里通告里写了"非计划性"措辞 | 【维护】 | 不可信通告字面 | 通告措辞待修订 |
| 检修期间人员误操作 | 【人为误操作】 | 【检修】 | 误操作独立于检修归类 |
| 通讯线松动晃一下恢复 | 【通讯故障】 | 【设备故障】 | 不检修设备 |
| 变更窗口外同设备引发的告警 | 【设备故障】 | 【变更】 | 不在窗口内 |
| 维护 + 变更都需要 | 既发维护通告也发变更通告 | 只发其一 | 通告双发 |
| 业务突增触发的 IT 功率告警（未发通告） | 【超电】 | 【设备故障】 | 业务侧原因 |
| 机房温湿度波动 | 【环境参数异常】 | 【设备故障】 | 自然 / 空调系统原因 |
| 设备轮巡引发的告警但未发通告 | 【设备故障】 | 【设备轮巡】 | 必须先有通告 |

## 五、判定特例补充（从实际通告中总结）

- 已发【检修】通告的"通信中断"（如电量仪通信中断、列头柜通信中断、AU 采集器导致多路电量仪通信中断）：
  - 根因是设备本体故障且走检修流程 → 归【检修】（打标注意写清故障原因 + 处理状态）
  - 不打【通讯故障】（通讯故障仅指"线松晃一下就恢复"的弱电链路类，无需检修设备）
- 弱电设备（AU 采集器、电量仪、HMI）故障引发的通信中断，只要**已发检修/维护通告** → 归【检修】【维护】，不归【通讯故障】
- 阿里中天变（阿里侧设施）的维保通告 → 归【维护】；若通告中有变更需求（如蓄电池更换需配合变更），提示需"维护通告 + 变更通告双发"
- 通告状态为"是否可操作/是否可以开始操作" = 待执行确认态 → 按检修打标要点标注"维修/维护未完成，准备工作已完成，待操作"
- 通告状态为"工作已完成，设备运行正常" → 表明已完成，打标时备注"已完成，恢复正常"
