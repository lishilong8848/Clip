# 告警打标推荐

## Overview

将 EA118 机房动环告警按《现场告警打标规则指引》分为**预期内（7 类）**与**预期外（6 类）**共 13 类标签。输入：一条或多条通告（设备检修 / 维保通告 / 设备轮巡 / 设备调整 / 变更通告 等）。输出：每条通告推荐一个或多个标签（仅标签名 + 精简标签内容）。

## 输出格式（必须遵守）

每条通告输出：

```
【标签名】标签内容（精简后，见下方精简规则）
```

每条最多 3 个标签，标签内容只保留核心信息，不得输出依据、注意或额外汇总说明。

### 标签内容精简规则（必须遵守）

标签内容 = 通告标题/名称，删除以下冗余信息，**只留核心内容**（设备编号 + 设备名称 + 动作/故障）：

1. **删除园区/楼栋定位**：EA118数据中心X楼、EA118_C01机房X楼、C01机房X楼、EA118园区X楼、XX配电间/冷站 等前缀
2. **删除月份**：9月份、10月份、2026-09 等时间词
3. **保留**：设备编号（如 A-445-TRB-202-3、D-201-G列-DC004、E-218-ES-501）、设备名称（电量仪、列头柜、AU采集器、制冷单元、蓄电池、消防系统）、动作/故障内容（通信中断检修、月度维护、轮巡、模式调整、软件更新）

示例对比：
- ❌【变更】EA118数据中心ABCDEH楼9月份消防月度维保超低风险变更（第三阶段）
- ✅【变更】消防月度维保变更（第三阶段）
- ❌【检修】EA118_C01机房D楼D-201-G列-DC004通信中断检修
- ✅【检修】D-201-G列-DC004列头柜通信中断检修

## 判定流程（Step 1 → 4 依次执行）

### Step 1：判断通告类型

识别通告中的类型标记：【设备检修】【维保通告】【设备轮巡】【设备调整】【变更通告】，对应候选标签：
- 【设备检修】 → 检修
- 【维保通告】 → 维护
- 【设备轮巡】 → 设备轮巡
- 【设备调整】 → 设备调整
- 【变更通告】 → 变更

### Step 2：核对"预期内打标三前提"

预期内标签成立的条件，缺一不可：
1. **已发通告**：窗口内（未发通告的同类操作导致的告警 → 预期外【设备故障】）
2. **窗口内**：操作在通告范围内/时间内（窗口外同设备告警 → 【设备故障】）
3. **动作与告警对应**：告警由该操作的正常步骤触发（误操作 → 【人为误操作】）

### Step 3：判定标签（含多标签场景）

- 默认单标签：按 Step 1 类型直接对应
- **多标签场景**（既发维护通告也发变更通告 → 【维护】+【变更】同标；有通告+期间有人为误操作 → 通告标签+【人为误操作】）
- 特判（易错点，见 references/rules.md 第四节）：
  - 检修/维护通告中出现"通信中断/通讯故障"字眼，但根因是设备本体故障 → 仍归【检修】/【维护】，不归【通讯故障】
  - 弱电设备（AU采集器、电量仪等）异常导致通信中断 → 视通告类型归【检修】或【维护】（若已发通告）
  - 【通讯故障】仅用于：无检修通告的弱电通讯链路问题，如"通讯线松动晃一下就好"的误告警场景
  - 阿里（含阿里中天变等阿里侧）计划性维护通告即使措辞写"非计划性" → 仍归【维护】

### Step 4：内部条件核对（仅用于分类，不输出备注）

本步只作内部判断，**不产生任何向外的依据、注意、备注或汇总**：

- 【检修】类判定时核对通告是否说明"维修未完成（原因+当前处理状态）"或"检修完成（是否完成+修复方式）"——仅用于选择标签，不写入标签内容
- 其他类可核对通告中的强制状态（如"是否可操作"类等待确认）——同样仅用于判断归属
- 预期外标签候选（【设备故障】/【通讯故障】/【超电】等）仅需在分类时判断是否缺少已发通告/窗口/动作对应关系，不要求生成"需分析根因"提示

参考规则中的易错点（如阿里措辞陷阱）仅参与分类判断，不得进入输出；最终输出只有【标签名】+ 精简标签内容。

## 判定原则

- 通告字面措辞不决定标签（阿里措辞陷阱）；实际动作类型确定标签
- 打标签需处理每条通告，不允许省略，不允许只给标签不给精简内容
- 规则细节、13 类标签全量定义、易错点速查见 `references/rules.md`，拿不准时读取该文件
