# 灯塔楼栋概览与未完成工作

> 本说明不是实时数据，也不授予权限。工具返回名为准，OpenClaw 展示可能带 `lighthouse_` 前缀。

## 适用场景
问各模块未完成/未结束工作总览、今日待办、分模块数量与明细、楼栋概览。

## 查询口径
- **未完成工作指截至当前的待办，不限于今日新增**；包含早于今天开始但尚未结束的事项。
- 未读取/无权限/超时的模块必须提示未知，**不能当作零条**。
- 各模块可能关联同一工作，分组数量**不相加为独立工作总数**。
- 只有明确“今天发生/新增/发布”才按业务时间过滤，普通今日待办直接看总览。

## discover 原生 API / 专用 tool
- 总览优先用 `pending_work`，按模块返回当前计数，必要时结合 `query(operation={api_id, params})` 各模块列表核实明细与分页。
- 问某一具体模块（维修/机柜/重保/水耗等）时用 `discover(keyword=…)` + `query` 对应接口，路径以 discover 返回为准。

## 记录 ID 与字段
- 总览中分组的数量与明细是当前状态快照；完整数量以接口统计或完整分页为准。
- 明细里的 record_id/batch_id/task_id 供继续追问时复用，不猜不补。

## 办理顺序/确认/超时
- 工作汇总只显示数量大于 0 的类别；用户明确要求全分类时才列零项。
- 读取失败/超时提示未知并说明模块，不自动隐藏。
- 总览只读；要办理再走各模块 `prepare_business`，用户确认后执行。

## 权限与禁止边界
- 查询范围由登录权限限定，不得扩大楼层/楼栋。
- 总览不是执行入口，不直接写删多维记录。

## 调用例子
`pending_work()` 读当前未完成分组 → 需要某模块明细时 `discover(keyword="维修")` → `query(operation={api_id:"GET /api/repair-management/records", params:{scope:"D", page:1, page_size:20}})` 核对明细与分页（其它模块以 discover 返回的真实接口为准，不把中文占位当 api_id）。
