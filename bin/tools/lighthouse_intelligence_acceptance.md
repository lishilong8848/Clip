# 助手与飞书智能体智能化验收

本轮继续使用共同的助手引擎、权限校验、业务查询、表单和投递恢复流程，不创建第二套业务服务。所有验收使用隔离数据、模拟模型或本地测试接口，不向真实飞书发送消息。

| 优化方向 | 实现与验收要点 | 回归测试 |
| --- | --- | --- |
| 连续追问 | 保存业务对象、最新条件和候选标识；日期、状态及楼栋纠正替换旧条件；第二条转明细，不返回旧数量 | test_lighthouse_task_context、test_lighthouse_intelligence_evaluation |
| 统一口径 | 通告待发、进行中、实际发送分开；条数与发送次数分开；学练题单与参与人数分开 | test_lighthouse_business_semantics、test_lighthouse_learning_participation |
| 完整查询 | 复用当前页，只补缺失页；最多3路跨楼栋并发；每次读取重验权限；预算、快照变化或失败不能声称全量 | test_lighthouse_business_semantics、test_lighthouse_intelligence_evaluation |
| 可靠记忆 | 只记用户明确要求的表达格式；按原账号保存；话题指代不外溢；不保存或继承旧表单值 | test_lighthouse_task_context、test_notice_memory_isolation、test_notice_memory_history |

## 保持的业务边界

- 操作仍由原页面/原确认表单执行；补充信息不等于确认，不跳过照片、工单或源表绑定校验。
- 公司知识库只沿用明确选择的公司知识库入口及其相关追问，不因普通业务、天气或新闻查询自动检索。
- 文件默认交付当前会话，未明确要求不转发给其他人。
- 本地共享数据仍仅为助手只读副本；缺失数据走原获准读取通道，不通过管理员刷新接口改动业务。
- 历史推荐仍走原通告记忆隔离和手填保护逻辑，不复制旧进度、人员、设备或周期到另一条业务。

## 验证限制

隔离测试可验证编排、权限、格式、去重和恢复，不能证明真实服务商对自然语言问题的正确率。上线前后仍需使用获准账号对实际模型做少量人工抽查，不在打包时额外进行收费模型请求或真实业务发送。

文件位置只对应可提取文字；Word不虚构排版页码，扫描件/OCR需核对原图。公式不重新计算。读取达到预算时明确保留不完整标记，不把样本当成全量。

## 语义理解与交付核验补强

- 不新增固定问句/回复字典。模型按当前问题及授权历史理解多个目标、指代和改写；复杂任务通过 `review_answer` 自述交付目标，程序只验证来源引用、附件回执和原业务确认计划。
- 学练参与与在职人数不再在共同模型入口提前返回固定答案。模型选择已有统计工具，学练继续复用原完整参与统计、权限及话题授权；后续可继续比较、生成附件，不只完成第一个子问题。
- `query_statistics` 只统计本轮已获准的查询快照：计数、按稳定身份去重、分组、求和及均值；不执行SQL、不联网、不写业务。保留缺失项和不完整标记，敏感字段不允许统计。
- 原生模型对有证据的答复补全不再仅限“过程文字”。只允许续读/统计原快照、核算与交付核验，最多一次本模型修正；不能重新查询、发送或执行业务。已显示的普通回复及回执未确认的任务仍不重跑。
- 文档连续编辑只记本人、原话题中经授权的文档标识及版本提示，由模型判断本轮是否指向它；修改前重新读取当前版本，保留未指定段落，不覆盖原附件。
- `evaluate_lighthouse_intelligence.py` 默认仅运行隔离模拟自检。显式 `--live` 后可对指定模型做真实推理评测，但接口与资料仍为合成测试数据；不读取生产会话，不发送飞书消息，不写正式业务表。密钥仅从 `LIGHTHOUSE_EVAL_API_KEY` 读取，不放命令参数和报告。
- 真实模式还需 `--endpoint` 和一个或多个 `--model`；报告区分 `offline-fixture` 与 `live-synthetic-data`，包括通过情况、读取次数和耗时。模拟通过不代表真实模型理解能力已经通过。

## 独立复核与长回复

- 共同回答入口在交付前发起独立、无工具的复核请求，以原问题、授权历史、可见证据及实际附件回执判断切题、漏项、范围及无依据结论；优先使用另一已配置模型。不是把用户问句映射为固定答案。
- 最多两次纯文字补充或重写，不重放业务、发送、查询或文件生成。原业务计划、确认表单及安全拒绝保持原流程。复核总预算45秒，异常或无法完整复核时明确说明，不能标记通过；已经判定不合格的草稿不直接交付。
- 复核只核对提供的证据节选，不等于已核验全部原始数据、图片或附件正文；缺证据不能靠重写创造事实。权限在复核及返回前重新检查，不改变原权限和会话归属。
- 最终正文按 Python Unicode 字符数判断：中文、英文及换行、空格、Markdown标记都计数，不按字节数或模型token计算。默认阈值为 `lighthouse_artifacts.LONG_REPLY = 3500`；等于阈值直接显示，超过阈值交付 `完整回答.md` 和简短说明。
- Markdown采用UTF-8，逐字保存复核后的完整正文，保留标题、列表、代码块、链接等原有格式，不附加或删改来源段落。正文SHA-256记入附件回执；既有来源和其他附件单独保留。复用原文件安全与大小限制，超限明确失败，不静默截断。
- 网页复用当前会话的附件预览、原文切换及下载；Markdown渲染继续进行HTML消毒。飞书复用原附件上传及分段回执，简短说明与文件均发送到原话题或原私聊；重试只补未成功部分。正式交付前不公开未复核草稿或先展示长文再替换附件。
- Python回归覆盖独立复核失败/纠正/权限撤回、阈值边界、多字节字符、正文一致、完整预览及原话题/私聊附件重试。`frontend/scripts/check-assistant-workspace.mjs --markdown` 使用隔离接口检查实际助手的标题/列表/代码、原文/下载、恶意HTML及360/402/440/1440像素预览。
