设计说明自由布局已降级为高级选项

  • 保留能力。原有的 GridStack 12 列自由拖拽、每页最多 16 个组件、按账号存服务端的布局同步全部保留，只是入口从「第一个组件上的自定义按钮」移到页面右上角，不再是首屏的默认心智。
  • 修掉的问题。现版本「自定义」按钮只渲染在排序第一的组件上（HomePage.vue 的 isFirst(item)），空布局时用户找不到入口；编辑态还并存上移下移、拖拽、resize 手柄三套排序机制。
  • 完整业务模块内嵌（module widget）建议改用抽屉。现版本允许把任意完整模块以 12×12 内嵌，多楼栋时按 scope 复制多份纵向堆叠（WidgetView.vue），滚动长度失控。本方案改为：点击待办行 → 右侧抽屉内办理，列表上下文不丢失。
  • 需后端配合。本队列依赖一个新的服务端「我的待办」聚合接口，返回结构化状态枚举（不再靠前端正则匹配中文状态词）、dueAt 时间戳与班次时间窗标记，以及可信的分页总数。

设计说明个人工作台重设计：从「可拼装仪表盘」到「班次行动中枢」

1定位收敛

现版本 10 种 widget 里 5 种是图表概览、4 种是待办办理、1 种是快捷入口，默认布局只给三张同等权重的白卡，首屏既不回答「今天做什么」也没有全局概览。新结构改为五层递进：班次上下文 → 今日焦点 → 本班必须完成 → 需要留意 → 运行概览，概览明确降级为「态势参考，不驱动本班动作」。

2排序口径改为班次驱动

现版本 businessTodos.ts 的排序只有三层优先级（逾期 → 状态含退回/异常/失败 → 其余），而水耗、学练、签名三类源根本不返回 dueAt，永远排最后——即使是当班必填项。新口径为本班必填 > 已逾期 > 今日到期 > 后续跟进，与运维的班次作业节奏对齐。

3persona 真正生效

现版本 personaFor 只影响 defaults() 的初始布局，用户保存过布局后永久失效；侧边栏菜单硬编码「个人工作台」，personaTitles 是死代码。新方案让五类角色各自拥有不同的焦点带组成、队列内容、快捷项与概览默认展开态，切换角色可见实质差异。

4数据完整性诚实呈现

现版本每个分组只显示「已读取 N 条」，用户无法判断是否漏了事项。新方案在每个优先级分组头部标注「共 N 项 · 已完整读取」或「已读取 30 项 · 仍有后续」，并把加载失败降级为区块级 inline 错误 + 单独重试，不污染其他区块。沿用现有实现「未知不当零」的原则。

5语义色与卡片层级

现版本所有 widget 是同一种白卡（1px 边框 + 1.6% 不透明度阴影），紧急待办与水耗趋势图视觉权重相同；--v2-blue 变量名叫 blue 值却是墨绿，成功/警告/错误色未在 dashboard.css 中定义。新方案建立三档卡片层级与完整语义色 token，且所有状态颜色 + 图标 + 文字三重传达。

6数据新鲜度升级为决策级信号

底表同步失败意味着「你看到的清单可能是陈旧的」，现版本只用一条弱 warning 提示。新方案在失败时升级为整幅危险色横幅并写明数据截止时间，明确告知「请勿据此判断为零」。

7去掉用 DOM 当状态机

现版本 protectedContent() 靠 document.querySelector('[data-v2-layout-protected="true"]') 判断班前检查是否填完。新方案中「班前检查是否完成」是焦点带的一个显式数据字段，由服务端返回，不再探测 DOM。

8移动端与桌面同构

现版本 MobileBrief 只给 3 个数字，与桌面 widget 内容无映射关系；GridStack 被 CSS 强改成 flex 列。新方案移动端是同一套信息结构的窄屏排布：sticky 班次条 → 2×2 焦点网格 → 全宽队列卡（主操作 ≥44px）→ 手风琴折叠的留意与概览。
