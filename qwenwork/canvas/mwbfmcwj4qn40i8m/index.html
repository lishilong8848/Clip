设计说明个性化边界：可调顺序，不可调范围

  • 允许。用户可调整六个区块内卡片的顺序与折叠状态，偏好按账号保存；首屏排序仍固定遵循「需立即处理 → 今日到期 → 风险异常 → 趋势与统计 → 常用入口」。
  • 禁止。个性化配置不能扩大数据范围：A 楼主管即使把「合同」卡片置顶，看到的仍只是 owningBuildingIds 含 A 的合同与 A 楼分摊金额。
  • 只读边界。首版工作台只做聚合与深链，不承载写操作；新增、审批、付款、删除一律回到原业务页面并由后端实时鉴权。
  • 需后端配合。本原型的全部差异依赖 /api/workbench/bootstrap 与 /api/workbench/sections/{key}：身份与范围由服务端下发，前端不得自行拼装权限。

设计说明对齐《差异化个人工作台规划方案 V0.1》的八项落地

1六块固定信息架构（§8.1）

身份与范围条 → 紧急待办 → 今日运行 → 业务进展 → 人员与值班 → 快捷入口，顺序固定不随个性化改变。顶部关键数字来自 bootstrap，与「核心数字」口径一致。

2身份与范围条（§8.1-1）

显示姓名、角色编码、数据范围、权限来源、策略版本与组织快照时间。A 楼主管的范围芯片为锁定态（不可切换、不展示其他楼栋入口与数量）；园区经理为可比较态。

3统一待办对象与 reason（§8.3）

每条待办带 P0–P3 + SLA 倒计时 + 来源 + reason。reason 直接回答「为什么出现在我的工作台」，例如「你是 A 楼主管；该合同归属 A 楼；距到期还有 14 天」，多来源事项标注合并数与 dedup 规则。

4分区独立来源状态（§8.5/§8.6）

每个区块自带 正常 / 延迟 / 不可用 / 权限不足 芯片。用控制条把「业务进展」切到延迟或不可用时，其余区块继续可用，不整页转圈；延迟时保留最近有效数据并标注「可能延迟 + 最近成功时间」。

5同口径承诺（§7.2）

每个分组与卡片都标注「卡片 N 条 · 明细 N 条」，点击数字进入的明细基于同一范围快照与派生规则；无法提供明细的数字不作为可操作 KPI。

6权限解释与拒绝演示（§9.2）

「为什么是这个范围」打开裁决抽屉：角色来源、命中规则、数据范围、字段白名单、策略版本与审计编号。「模拟越权访问 B 楼」展示服务端拒绝文案模板与 DENY_SCOPE_MISMATCH，且不泄露 B 楼记录数量。

7六类角色首屏差异（§6.1/§8.8）

园区经理 / A 楼主管 / 楼栋工程师 / 值班员 / 园区主管工程师 / 综合管理员各自的第一优先级不同：经理看跨楼风险与审批，A 楼主管只看 A 楼，工程师看阻断与闭环，值班员看漏检与 SLA，主管工程师看专业风险与 110kV 只读，综合管理员看采购合同授权临期。

8零影响 Demo 纪律（§9）

全页标注「演示数据 · 规划示意｜非生产权限」；不调用任何业务接口；所有处理动作均为深链示意并由后端再次鉴权；110kV 站视图不出现分合闸、倒闸或定值入口。

对接清单前后端接口契约（§8.5 / §8.10.11）· 阶段 3 开工依据

工作台接口契约：方法、响应要点与前端消费规则
接口响应要点前端消费规则
GET /api/workbench/bootstrapidentity{subjectId, roleIds, scope, capabilities, orgSnapshot, policyVersion}、keyNumbers[]、urgentTop[]、sectionStates{}只消费服务端返回的可见导航/数据/动作/原因说明；不得自行拼装权限；响应尽量小
GET /api/workbench/sections/{key}
key ∈ urgent | ops | biz | people		{items[], total, snapshotId, sourceStatus, lastSuccessAt}首屏后按区块懒加载；每区块独立 loading / empty / error / stale / permission-denied；禁止整页长期转圈
GET /api/workbench/drilldown{items[], total, snapshotId}携带 drilldownKey + snapshotId；total 必须等于卡片数字（同口径承诺）
GET /api/workbench/messages{items[{id,objectId,state,cooldownUntil}]}通知只携带业务标识与最小摘要；打开时重新鉴权；撤权后旧消息不可打开明细
POST /api/exports/request{token, validFor=15m, watermark, auditId}单次短时令牌；范围裁剪 + 字段白名单 + 行数阈值；权限源异常时失败关闭
  • sourceStatus 枚举与前端表现：ok 正常芯片；stale 保留最近有效数据 + 「可能延迟」+ 最近成功时间；down 区块级错误 + 单独重试；deny 「权限已变更」横幅 + 拒绝面板（原因码 + 审计编号）。任一分区降级不影响其他分区。
  • 竞态防护：所有区块请求携带 requestKey / version；旧响应不得覆盖新选择；筛选与展开先本地反馈（P95 < 100ms），已有数据弹层 P95 < 150ms。
  • 字段裁剪：F0–F3 白名单由服务端执行；敏感字段不占位泄露；导出写入导出人、时间、规则版本、范围与水印编号。
  • 阶段 3 验收门槛：摘要与明细逐条一致；主要性能与错误态达标；A 楼样本人员四个核心模块数据可准确归属后方可进入试点。
