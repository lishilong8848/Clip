# 个人工作台 前后端接口契约 · 阶段 3 对接清单

**依据**：《南通全景运维平台差异化个人工作台规划方案（V0.1 评审稿）》§7、§8.3、§8.5、§8.6、§8.7、§8.10、§11
**对应原型**：`index.html`（Canvas Frame「个人工作台 · V0.1 评审稿对齐」）
**状态**：对接草案 · 仅规划与 Demo 阶段结论，生产实施以阶段 2 权限底座落地后的联调为准
**边界**：首版工作台**只读聚合 + 深链**；所有写操作回到原业务模块并由后端实时鉴权。前端隐藏卡片或菜单只改善体验，**不是安全边界**。

---

## 0. 总则（先读这五条）

1. **身份只信服务端。** 所有接口由服务端注入 Principal V2；前端不传 role / buildings / name，传了也只作为「进一步收窄」的请求意图，不能扩大允许范围。
2. **先过滤后聚合。** 行级过滤必须在数据库查询或服务端聚合阶段完成；禁止返回全量由前端过滤。计数、金额、趋势、排行、图表与明细使用**同一份过滤结果**。
3. **同口径承诺。** 任何卡片数字必须能下钻到条数完全一致的明细（`total === 卡片数字`），且基于同一 `snapshotId`。做不到明细的数字，`actionable=false`，前端标「历史口径 · 非可操作 KPI」。
4. **分区独立降级。** 四个分区（urgent / ops / biz / people）各自返回 `sourceStatus`；单区失败不得拖垮其他区，不得整页转圈。
5. **失败关闭。** 审批、导出、授权、付款、110kV 敏感写等高风险动作，权限源异常时一律拒绝，不降级执行。

## 1. Principal V2（所有接口的隐含输入）

服务端从签名会话解析并注入，响应中回显供前端展示与审计对齐：

| 字段 | 类型 | 说明 |
|---|---|---|
| subjectId | string | 服务端校验后的飞书 open_id；一人一号，冲突即隔离 |
| roleIds | string[] | 角色编码集合，如 `BUILDING_SUPERVISOR` |
| scope | object | `{campus, buildings[], professions[], stations[], shift?}`；空交集即拒绝范围型访问 |
| capabilities | string[] | 动作集合，首版工作台仅 `*.read` 与深链 |
| orgSnapshot | object | 部门/岗位/用户组/直属负责人 + `snapshotAt`；仅解释用，不单独授权 |
| policyVersion | string | 策略版本；变化即失效缓存与会话 |

**有效数据范围 = 本次请求范围 ∩ Principal V2 允许范围。**

## 2. 接口清单

### 2.1 `GET /api/workbench/bootstrap`

首屏一次性小响应：身份、范围、顶部关键数字、最紧急待办、各分区状态。

```jsonc
{
  "identity": {
    "subjectId": "ou_****",                 // 展示时脱敏
    "name": "刘小杏",
    "roleIds": ["BUILDING_SUPERVISOR"],
    "roleLabels": ["A 楼主管"],
    "scope": { "campus": "Nantong", "buildings": ["A"], "professions": [], "stations": [], "shift": null },
    "scopeFixed": true,                      // true → 前端禁用楼栋切换器并显示「不可切换」
    "capabilities": ["today.read", "purchase.review"],
    "orgSnapshot": { "groups": ["A 楼主管"], "post": "设施主管", "snapshotAt": "2026-11-11T05:30:00+08:00" },
    "policyVersion": "2026.08.01-01"
  },
  "keyNumbers": [
    {
      "key": "urgent_p01",
      "label": "A 楼 P0 / P1",
      "value": 3, "unit": "项",
      "tone": "bad",                          // bad | warn | ok | info
      "sub": "P0 1 · P1 2",
      "delta": "较昨日 +1",                   // KPI 必须带趋势上下文
      "drilldownKey": "urgent?priority=P0,P1",
      "derivation": "count(urgent where scope∈principal and priority in (P0,P1))",
      "actionable": true                      // false 时前端标「历史口径」且不可下钻
    }
  ],
  "urgentTop": [ /* TodoObject[0..2]，结构见 §3 */ ],
  "sectionStates": { "urgent": "ok", "ops": "ok", "biz": "ok", "people": "ok" },
  "sync": { "sourceStatus": "ok", "lastSuccessAt": "2026-11-11T11:14:00+08:00" }
}
```

约束：
- `keyNumbers[].value` 必须由与 `sections/urgent` **相同的过滤结果**计算；`derivation` 字段供前端与测试核对口径。
- `scopeFixed=true` 时，任何携带其他楼栋参数的后续请求都应被拒绝（见 §6 原因码）。
- 响应目标 < 8 KB；不放列表全量。

### 2.2 `GET /api/workbench/sections/{key}?snapshotId=`

`key ∈ { urgent | ops | biz | people }`，首屏后懒加载。

```jsonc
{
  "key": "urgent",
  "snapshotId": "SNAP-20261111-0530",
  "sourceStatus": "ok",                       // ok | stale | down | deny
  "lastSuccessAt": "2026-11-11T11:14:00+08:00",
  "total": 6,                                 // 必须等于前端卡片/分组合计
  "page": { "size": 20, "next": null },
  "items": [ /* key=urgent → TodoObject[]；ops/biz → CardObject[]；people → PeopleObject */ ]
}
```

- `urgent.items` 服务端已按 §8.7 排序：`priority → 是否逾期 → dueAt → 业务影响 → 首次发生时间`；前端不再重排。
- `ops` / `biz` 的 `CardObject`：`{ icon, title, line:{value,unit,label}, list:[{tone,text}], chart?:{type:'bar',values[],labels[],unit}, foot, drilldownKey }`。`chart.values` 之和或末值必须与 `line.value` 可解释对应。
- `people`：`{ left:{title, meter:[on,total], meterLabel, list[], foot}, right:{title, list[], foot} }`；联系方式按 §5 脱敏后下发。
- 错误响应：`403 {reasonCode, explanation, auditId}`；`503 {reasonCode, retryAfterSec}`；`409 SNAPSHOT_MISMATCH`。

### 2.3 `GET /api/workbench/drilldown?drilldownKey=&snapshotId=`

```jsonc
{ "snapshotId": "SNAP-20261111-0530", "total": 3, "items": [ /* 明细行，字段随 drilldownKey 类型 */ ] }
```

- **硬约束**：`total` 必须等于触发下钻的卡片数字；测试以「卡片 8 条，明细正好 8 条」为通过标准。
- `snapshotId` 与卡片不一致返回 `409 SNAPSHOT_MISMATCH`，前端提示重新读取而非混用两批数据。
- 明细行不得包含超出当前角色字段白名单的字段（§5）。

### 2.4 `GET /api/workbench/messages`

```jsonc
{
  "cooldownWindowSec": 300,
  "items": [
    { "id": "MSG-…", "objectId": "AL-2026-1191", "objectType": "alarm",
      "title": "A 楼 4F 冷塔风机 2 号 振动越限 P0 催确认",
      "when": "11:16",
      "state": "enter",                        // enter | view | scope | closed
      "minSummary": "P0 · 未确认",             // 最小摘要，不含敏感运行数据
      "cooldownUntil": "2026-11-11T11:21:00+08:00" }
  ]
}
```

- 同一 `dedupKey` 在冷却窗口内不重复下发；状态恶化或责任人变化可重新提醒（§8.7）。
- `state` 四态的前端表现：`enter` 可进入；`view` 仅查看；`scope` 范围已变化（打开为仅查看摘要）；`closed` 对象已关闭（仅归档摘要）。
- 消息**只携带业务标识**；打开时后端重新校验用户、角色、对象与楼栋范围；撤权后旧消息不得继续打开明细。

### 2.5 `POST /api/exports/request`

```jsonc
// req
{ "sectionKey": "biz", "drilldownKey": "biz:contract", "format": "xlsx", "rowCount": 1200 }
// 200
{ "token": "EXP-20261111-0031-7f3a", "validForSec": 900, "singleUse": true,
  "watermark": "WM-20261111-0031", "auditId": "DEC-20261111-004839",
  "scopeEcho": { "buildings": ["A"] }, "fieldPolicy": "F2-masked" }
// 403 {reasonCode:"DENY_SCOPE_MISMATCH"|…}  409 {reasonCode:"DENY_SOD_CONFLICT"}  503 {reasonCode:"FAIL_CLOSED"}
```

- 单次、短时（≤15 分钟）、用后即失效；范围裁剪 + 字段白名单 + 行数阈值（默认 ≤2000，超出转人工）。
- 申请人 ≠ 审批人；共享值班账号不得发起。
- 水印编号写入审计：导出人、时间、规则版本、范围、水印号。

## 3. 统一待办对象 TodoObject（§8.3）

| 字段 | 类型 | 说明 |
|---|---|---|
| id / type / source | string | 唯一编号 / 待办类型 / 来源模块 |
| title / summary | string | 可快速判断的标题 + 一行摘要 |
| scope | object | 园区、楼栋、专业、站点、对象关系（本人/班组/负责人/协办） |
| priority / status | `P0..P3` / `pending|processing|done|overdue` | 结构化枚举，**禁止中文自由文本** |
| dueAt / owner | ISO8601 / `{id,name}` | 截止与当前责任人；协办 `coOwners[]` |
| actionUrl | string | 受控深链；目标页后端再次鉴权 |
| **reason** | string | 可解释性字段，模板：`你是{roleLabel}；{scopeHit}；{timeHit}。` 例：`你是 A 楼主管；该合同归属 A 楼；距到期还有 14 天。` |
| sourceStatus | `ok|stale|down|deny` | 该条来源健康度 |
| dedupKey / mergedSourceIds | string / string[] | 业务对象ID+事项类型+数据范围；合并不丢证据 |
| sla | `{confirmBy, escalateAt}` | P0 立即置顶/5′确认/15′升级；P1 30′/2h；P2 当班；P3 计划日 |

前端表现映射：`priority` → 行左侧色槽与分组；`sla.confirmBy` → 倒计时文案；`reason` → 桌面常显、移动点按展开；`mergedSourceIds.length>1` → 「N 来源」标记。

## 4. sourceStatus 四态与前端表现（§8.5/§8.6）

| sourceStatus | 芯片 | 区块表现 | 前端行为 |
|---|---|---|---|
| ok | 绿「来源正常」 | 正常渲染 | — |
| stale | 琥珀「数据延迟 · 最近成功 {t}」 | 保留最近有效数据 + 区块内「可能延迟」提示 | 后台重试；**不把旧数据伪装成实时** |
| down | 红「来源不可用」 | 区块级错误卡 + 「重试本区块」 | 其他区块不受影响；不整页转圈 |
| deny | 蓝「权限不足 · 已拒绝」 | 「权限已变更」横幅 + 拒绝面板（原因码+审计编号） | 立即清除该区块卡片缓存与深链 |

空态必须带口径说明（如「P0–P3 且状态≠已完成 共 0 条；七个来源均正常，非读取失败」），**不允许用空白区域代替空状态**。

## 5. 字段敏感度与脱敏（§8.10.8）

| 等级 | 示例 | 园区经理 | A 楼主管 | 楼栋工程师 | 值班员 | 综合管理员 |
|---|---|---|---|---|---|---|
| F0 公共运营 | 楼栋状态、事件数量、当班状态 | 可见 | 可见(仅A) | 可见(楼∩专业) | 可见(当班) | 可见 |
| F1 内部运维 | 设备、巡检、工单、施工进度 | 可见 | 可见(仅A) | 可见(楼∩专业∩关系) | 可见(本人/班组) | 关联摘要 |
| F2 敏感业务 | 合同金额、付款账号、手机号 | 白名单字段 | 摘要/脱敏 | 摘要/脱敏 | 脱敏 | 白名单字段 |
| F3 高敏安全 | 权限策略、110kV 详细操作、资质 | 仅风险总览 | 不可见 | 不可见 | 不可见 | 不可见 |

- 手机号下发即掩码（`138****4021`）；合同金额按 `buildingAllocations[本楼]`，无分摊标「共享合同」且不进楼栋 KPI。
- 人员池身份证、手机号明文、邮箱、生日、学历、照片**不进入鉴权输入，权限服务不预加载**。
- 敏感字段不占位泄露：无权字段直接不下发，而非下发空串或 `***` 占位结构。

## 6. 拒绝原因码与解释模板（§8.10.9/§8.10.11）

`DENY_IDENTITY_UNKNOWN`、`DENY_IDENTITY_AMBIGUOUS`、`DENY_NOT_ACTIVE`、`DENY_ROLE_UNMAPPED`、`DENY_SCOPE_EMPTY`、`DENY_SCOPE_MISMATCH`、`DENY_OBJECT_UNCLASSIFIED`、`DENY_NOT_ON_DUTY`、`DENY_BACKUP_INACTIVE`、`DENY_DELEGATION_EXPIRED`、`DENY_SOD_CONFLICT`、`DENY_SOURCE_STALE`、`DENY_EXPLICIT`、`FAIL_CLOSED`。

解释模板（前端拒绝面板原样渲染，不补充其他楼栋数量或敏感字段）：

> 当前账号以【角色】访问【对象】，所需动作【动作】；命中的有效范围为【园区/楼栋/专业/班次】，对象范围为【对象标签】；因【标准原因码】拒绝。规则版本【policy_version】，人员/组织快照时间【source_version】。

响应必须携带 `auditId`（decision_id），用于申诉与排障。

## 7. 竞态、缓存与时效（§11.1/§8.10.11）

| 项 | 约定 |
|---|---|
| 竞态防护 | 每请求携带 `requestKey = sectionKey+roleIds+scope+policyVersion` 与自增 `version`；服务端回显；前端丢弃 `version` 落后的响应 |
| 本地反馈 | 筛选/展开/排序 P95 < 100ms 本地生效；已有数据弹层 P95 < 150ms；后台异步刷新并标「更新中」 |
| 权限快照 | 普通页面 ≤5 分钟；低风险只读 ≤15 分钟；审批/导出/附件/付款 ≤5 分钟，超龄直接拒绝 |
| 立即失效 | 离职、调岗、调楼、角色/代理/组织/策略变化 → 提升 policyVersion、清缓存、失效会话，不等 TTL |
| 高风险动作 | 每次实时鉴权；**服务端确认前不得显示最终成功**；状态机：处理中 → 已成功 / 失败可重试 |
| 组织快照 | 飞书不可用时用最近有效快照并标注 `snapshotAt`；超 §11.5 上限即失败关闭；降级期不放大新授权 |

## 8. 前端消费规则（写进前端 code review 清单）

1. 只渲染服务端返回的可见导航、数据、动作与原因；不自行拼装或推断权限。
2. 不把 `sourceStatus=stale` 的数据展示为实时；必须显示 `lastSuccessAt`。
3. 数字无 `drilldownKey` 且 `actionable=false` 时，标「历史口径 · 非可操作 KPI」，不提供下钻。
4. 深链一律携带 `drilldownKey + snapshotId`；打开时接受 `409 SNAPSHOT_MISMATCH` 并提示重读。
5. 消息点击、导出、下载附件：每次重新鉴权；撤权后旧入口给出标准拒绝而非空白。
6. 单区块重试只刷新该区块；保留用户当前筛选与草稿。
7. 移动端任务卡只呈现 级别/对象/期限/状态/一个主操作；reason 与对象编号在抽屉中查看。
8. 任何「成功」提示必须来自服务端确认；本地乐观更新失败时精准回滚对应字段并保留草稿。

## 9. 阶段 3 验收门槛与测试矩阵（摘要）

**退出标准**：摘要与明细逐条一致；四分区独立降级互不拖垮；主要性能与错误态达标；A 楼样本人员四个核心模块数据可准确归属。

| 维度 | 必须覆盖 | 通过标准 |
|---|---|---|
| 角色 × 页面 | 六角色 × 六区块 | 菜单与直接 URL 均符合策略 |
| 角色 × 楼栋 | A 访问 A / A 访问 B / 全园区 / 无楼栋数据 | A 楼主管对 B 楼响应数据为 0，**不泄露存在性** |
| 接口篡改 | query / body / 对象 ID / 分页 token / 导出参数 | 服务端仍拒绝并产生审计 |
| 同口径 | 卡片 → drilldown | total 完全一致；snapshot 一致 |
| 降级 | 四分区 × 四态 | 单区降级不影响其他区；stale 不伪装实时 |
| 字段 | 手机号/合同原件/金额/付款账号/附件 | 按白名单脱敏或拒绝；下载链接不可绕过 |
| 多角色 | 兼岗、临时授权、显式拒绝 | 能力与范围不跨域串权；拒绝优先 |
| 生命周期 | 调岗/离职/停用/授权到期 | 旧会话、旧标签页、旧消息链接全部重新鉴权 |

**上线否决条件**：A 楼主管经任何入口取得 B 楼数据；汇总与明细口径不一致；缺失楼栋被放大为全园区；撤权后旧会话仍可访问；高风险动作在服务端确认前显示最终成功。

## 12. Mock Server（阶段 3 前端先行联调）

位置：`mock-server/server.js`（零依赖，仅 `node:http`）；自检：`mock-server/selftest.js`（27 项断言）。

```bash
node mock-server/server.js 8787     # 启动，默认端口 8787
node mock-server/selftest.js       # 契约自检：同口径 / 范围拒绝 / 四态 / 排序 / 枚举
```

| 端点 | 说明 |
|---|---|
| `GET /api/workbench/bootstrap?role=` | 身份、scopeFixed、capabilities、keyNumbers（服务端派生）、urgentTop、sectionStates |
| `GET /api/workbench/sections/urgent?role=&snapshotId=&sourceStatus=&buildings=` | 行级过滤 + 服务端排序后的统一待办列表 |
| `GET /api/workbench/drilldown?drilldownKey=&snapshotId=&role=` | 同口径明细；`total` 恒等于卡片数字 |
| `GET /api/workbench/_mock/help` | mock-only 参数与快照/策略版本说明 |

**Mock-only 约定（生产不存在）**：角色用 `role=` 或 `x-mock-role` 指定（生产由签名会话解析）；分区降级用 `sourceStatus=` 模拟；`buildings=` 仅作「收窄意图」演示——对 `scopeFixed` 角色传入范围外楼栋会返回 `403 DENY_SCOPE_MISMATCH` + 解释模板 + 审计编号，且不泄露目标楼栋记录数量。

**自检覆盖**：bootstrap 数字 == 分区中同优先级条数 == drilldown 总数；`snapshotId` 不一致 → `409 SNAPSHOT_MISMATCH`；`down → 503+retryAfter+lastSuccessAt`、`stale → 200+最近成功时间`、`deny → 403+解释`；服务端已排序、前端不重排；每条待办含 reason/dedupKey/sla/sourceStatus/actionUrl/owner 且 priority/status 为结构化枚举；duty 巡检 `5/8` 与点检明细同口径；未知路由 404、未知角色 400 `DENY_ROLE_UNMAPPED`。

**纪律**：静态原型 `index.html` 保持零 API 调用（§9）；mock server 仅用于阶段 3 前端按契约先行开发与自动化测试，二者不互相依赖。fixtures 与原型同值，任何一侧改数都需同步另一侧并重跑 `selftest.js` 与原型验证脚本。
